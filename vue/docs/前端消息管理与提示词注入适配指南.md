# 前端消息管理与提示词注入适配指南

## 概述

本后端迭代为对话系统新增了以下能力，前端需要相应适配：

1. **会话级配置**：新建/更新会话时可配置「展示给 AI 的最大消息数」「最大工具调用深度」「历史后提示词」。
2. **消息结构扩展**：历史消息新增 `depth`（消息深度）与 `isSeeable`（AI 是否可见）字段。
3. **隐藏/恢复消息**：可批量隐藏指定消息，隐藏后 AI 对话时看不到，但历史接口仍返回。
4. **注入提示词**：用户可预定义提示词（`user_insert_prompt`），聊天时按 `depth` 注入到历史中间指定位置。

---

## 一、会话创建/更新新增参数

### 1.1 创建会话 `POST /ai/conversation/create`

原有参数不变，新增三个可选参数：

| 参数                   | 类型     | 默认值 | 说明                                      |
|----------------------|--------|-----|-----------------------------------------|
| `maxMessages`        | number | 100 | 展示给 AI 的最大消息数（<=0 时回退默认）                |
| `maxToolCallDepth`   | number | 10  | 最大工具调用深度（<=0 时回退默认），超过后 SSE 返回 error 事件 |
| `afterHistoryPrompt` | string | 无   | 历史后提示词，紧跟历史消息之后发给 AI                    |

```json
{
  "conversationName": "数学助手",
  "systemPrompt": "你是一个数学老师",
  "apiKey": "sk-xxx",
  "model": "deepseek-ai/DeepSeek-V3",
  "baseUrl": "https://api.siliconflow.cn",
  "userId": "u-001",
  "maxMessages": 50,
  "maxToolCallDepth": 5,
  "afterHistoryPrompt": "请用中文回答，步骤尽量详细"
}
```

### 1.2 更新会话 `POST /ai/conversation/update`

新增同名字段，均为可选（null/不传 = 不修改）：

```json
{
  "conversationId": "xxx",
  "maxMessages": 80,
  "maxToolCallDepth": 3,
  "afterHistoryPrompt": "请用简体中文回答"
}
```

> **前端建议**：新建会话表单可增加「高级设置」折叠区，让用户配置这两个数字；`afterHistoryPrompt` 可作为会话的"附加指令"输入框。

### 1.3 会话列表返回

`GET /ai/conversation/getAll` 返回的会话对象同样包含这三个新字段（`maxMessages`/`maxToolCallDepth`/`afterHistoryPrompt`），前端可在会话设置面板中回显。

## 二、历史消息结构变化

### 2.1 getHistory 返回的新字段

`POST /ai/conversation/getHistory` 返回的每条消息新增两个字段：

| 字段          | 类型              | 说明                                    |
|-------------|-----------------|---------------------------------------|
| `depth`     | number          | 消息深度，从 0 开始（语义见 2.2）                  |
| `isSeeable` | boolean \| null | AI 是否可见。`false` = 已隐藏；`null`（旧数据）视为可见 |

示例：

```json
{
  "code": 1,
  "msg": null,
  "data": [
    { "role": "USER",     "content": "计算 2+3*4",  "depth": 0, "isSeeable": true },
    { "role": "ASSISTANT", "content": null,        "depth": 0, "isSeeable": true,
      "toolCalls": [{ "id": "call_1", "type": "function", "functionName": "calculator",
                      "arguments": "{\"expression\":\"2+3*4\"}", "result": "14" }] },
    { "role": "TOOL",     "content": "14",          "depth": 0, "isSeeable": true,
      "toolCallId": "call_1", "toolName": "calculator" },
    { "role": "ASSISTANT", "content": "结果是 14",   "depth": 1, "isSeeable": true },
    { "role": "USER",     "content": "再算 10/2",    "depth": 0, "isSeeable": false }
  ]
}
```

> 注意：消息角色仍是 `USER`/`ASSISTANT`/`TOOL`/`SYSTEM` 大写字符串，字段名未变。

### 2.2 depth 语义（前端展示依据）

- 用户消息：`depth = 0`
- 第 r 轮工具调用的 `ASSISTANT`(tool_calls) 与其后跟随的 `TOOL` 结果消息：`depth = r`
- 该轮最终的 `ASSISTANT` 文本回复：`depth = 最终轮次`
- 新一轮用户消息重新从 0 开始

**前端用途**：

1. 工具调用卡片可显示"第 N 轮"角标（按 depth 分组）。
2. 注入提示词的位置选择依据（见第四节）。

## 三、隐藏/恢复消息

### 3.1 接口

**批量隐藏** `POST /ai/conversation/hideMessages`

```json
{ "conversationId": "xxx", "messageIndexes": [0, 3, 5] }
```

**批量恢复** `POST /ai/conversation/showMessages`

```json
{ "conversationId": "xxx", "messageIndexes": [0, 3, 5] }
```

- `messageIndexes`：0-based 索引，与 `editMessage`/`deleteMessage` 一致，可重复（服务端自动去重）。
- 任一索引越界 → 整体报错（`code: 0`，消息："消息索引越界，历史共 N 条消息，索引范围 0-(N-1)"），不会部分成功。
- 成功返回：`{ "code": 1, "msg": "已隐藏 3 条消息" }`。

### 3.2 行为说明

| 行为    | 说明                                                                                                    |
|-------|-------------------------------------------------------------------------------------------------------|
| AI 侧  | 隐藏后构建消息时该条被过滤，AI 完全看不到                                                                                |
| 前端侧   | `getHistory` **仍返回**隐藏消息（`isSeeable: false`），依然展示给用户看                                                 |
| 工具链连带 | 隐藏一条 `TOOL` 消息时，服务端会自动连带丢弃其配对的 `ASSISTANT`(tool_calls) 消息（反之亦然），保证发给 AI 的消息链完整 —— **前端提示用户隐藏TOOL的后果** |
| 当前消息  | 正在发送中的用户消息不会被隐藏（服务端先追加再构建）                                                                            |

### 3.3 前端交互建议

```
┌─────────────────────────────────────────────┐
│ 用户: 计算 2+3*4              [⋯ 操作菜单]    │
│  · 编辑消息                                  │
│  · 删除消息                                  │
│  · 🙈 隐藏（AI 将看不到）  ← 新增             │
├─────────────────────────────────────────────┤
│ 用户: 再算 10/2   [已隐藏]      [⋯ 操作菜单]  │
│  · 恢复显示（让 AI 重新可见）   ← 新增        │
└─────────────────────────────────────────────┘
```

- 支持**批量选择**：长按/勾选进入多选模式 → 底部功能栏出现「隐藏」按钮。
- 隐藏后的消息样式：半透明 + 灰色遮罩 + "已隐藏"角标；内容仍可查看。

## 四、注入提示词（新功能）

### 4.1 概念

- 用户可预先定义若干条提示词（存 `user_insert_prompt` 表），每条带有 `depth` 属性。
- 聊天请求携带 `insertPromptIds` 时，对应提示词会被**注入到历史中间**：插入到「历史中最后一条 `depth` 相同的消息」之后；若历史中没有该 depth 的消息，则追加到历史末尾。
- 注入内容以 `system` 角色独立消息发给 AI（AI 将其视为指令）。

### 4.2 提示词管理接口 `/ai/insertPrompt`

**创建** `POST /ai/insertPrompt/create`

```json
{ "userId": "u-001", "promptName": "工具结果复述规则", "content": "引用工具结果时请带上原始数值", "depth": 1 }
```

**更新** `POST /ai/insertPrompt/update`（仅更新非 null 字段）

```json
{ "id": 1, "userId": "u-001", "content": "引用工具结果时请带上原始数值与单位", "depth": 2 }
```

**删除** `POST /ai/insertPrompt/delete`

```json
{ "id": 1, "userId": "u-001" }
```

**列表** `POST /ai/insertPrompt/list`

```json
{ "userId": "u-001" }
```

返回：`{ "code": 1, "data": [ { "id": 1, "userId": "u-001", "promptName": "...", "content": "...", "depth": 1, "createTime": "..." } ] }`

> `depth` 合法性：`>= 0`，非法值（null/负数）创建时按 0 处理。删除/更新有归属校验（userId 必须匹配），否则返回"无权修改该提示词"。

### 4.3 前端 UI 建议

```
┌── 注入提示词管理 ──────────────┐
│ [＋ 新建提示词]                 │
│ ┌────────────────────────────┐ │
│ │ 名称: 工具结果复述规则        │ │
│ │ 内容: 引用工具结果时请带数值  │ │
│ │ 注入位置: 在深度：1        │ │
│ │ [保存] [删除]                │ │
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

- **注入位置选择**：用户输入数字；若某 depth 在当前对话中不存在，提示词会被追加到历史末尾。

### 4.4 聊天时注入

`POST /ai/chat`（以及 `/ai/chat/deep-thinking`）请求体新增 `insertPromptIds`：

```json
{
  "conversationId": "xxx",
  "message": "继续",
  "insertPromptIds": [1, 3]
}
```

- 多条提示词按请求顺序、同 depth 顺序注入。
- 传不存在的 id：服务端忽略并记录 warn，**不影响对话**。

**前端交互流程（推荐）**：

```
用户发送消息
    │
    ├─ 普通模式：insertPromptIds = []
    │
    └─ 注入模式（功能栏新增「注入提示词」按钮）：
        点开后弹出已保存提示词列表，勾选要注入的提示词
        → 确认后生效
```

## 五、边界情况与注意事项

| 场景                    | 说明                                                 | 前端建议                              |
|-----------------------|----------------------------------------------------|-----------------------------------|
| 旧会话历史                 | `isSeeable` 为 `null` → 视为可见；`depth` 为 0            | 渲染时按 `isSeeable !== false` 判断是否隐藏 |
| 隐藏 tool 消息            | 配对的 assistant(tool_calls) 被服务端连带丢弃                 | 操作确认框说明连带效果                       |
| `maxToolCallDepth` 超限 | SSE 收到 `{"type":"error","message":"工具调用次数过多,已终止"}` | 现有错误横幅逻辑即可覆盖                      |
| 注入提示词缺失               | 传了不存在的 id，服务端静默忽略                                  | 正常展示对话，无需报错                       |
| `maxMessages` 截断      | 历史超过上限时 AI 只看到最近 N 条                               | 前端可在会话设置中显示当前生效值，避免用户困惑           |
| 消息索引                  | 隐藏/恢复/编辑/删除均使用 0-based 索引                          | 注意删除后索引会前移，隐藏/恢复不会改变索引            |
| 会话列表回显                | getAll 返回新字段                                       | 会话卡片可显示"AI 可见消息数上限"等              |

## 六、快速自测清单

1. 创建会话带 `maxMessages=5, maxToolCallDepth=3, afterHistoryPrompt="请用中文回答"` → `getAll` 确认字段落库；`update` 修改 `afterHistoryPrompt` 后重新 `getAll` 验证。
2. 连续对话（启用工具）→ `getHistory` 检查 `depth` 递增、`isSeeable` 为 true、ASSISTANT(tool_calls)+TOOL 成对。
3. `hideMessages` 隐藏第 1 条用户消息 → 继续聊天，确认 AI 回复不引用该消息；`showMessages` 恢复。
4. `insertPrompt/create` 建一条 depth=1 的提示词 → 聊天带 `insertPromptIds`，观察注入效果；不带则不注入。
5. 触发多轮工具调用直到超过 `maxToolCallDepth` → 收到 `工具调用次数过多` error 事件。
